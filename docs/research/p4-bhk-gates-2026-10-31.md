# P4 BHK 正式门禁离线交付记录（2026-10-31）

本页记录执行证据，不另设 roadmap。规范为 [BHK 正式验收 v2](../operations/bhk-acceptance.md) 和 [ADR-0025](../architecture/decisions/ADR-0025-bhk-formal-acceptance.md)，正式状态见 [status](../upgrade/status.md#status-20261031-p4)。本轮没有校园请求、真实 profile/密码读取、认证、Candidate 构建、提交、推送或发布。

## 实现交付

- livegate 当前只生成 evidence v2，公开摘要和 promotion lock 同为 v2；Candidate/release manifest、六平台资产及两个 helper 保持 v1 集合。历史 v1 bundle/lock 独立只读审计，不改写、不补字段、不声称线上 provenance 已复验。
- 正式 runner 实际文件名、大小、SHA-256 与 manifest test_tools 对应平台项绑定，开始前和执行后验证。公开摘要携带 runner_sha256；promotion 将三份认证和两份辅助摘要与同一 Candidate helper 比较。旧 Candidate 混搭新 helper 拒绝。
- BHK 强制 bind-ip；物理有线/Wi-Fi、唯一所选 IPv4、默认路由和覆盖路由约束，命令前/中/后快照。检测到变化后 sticky 停止，含 cleanup；QR 私有 TTY 子进程透传绑定。系统 DNS/PKI 保持，不声称路由锁或全部 OS 流量计数。
- 安装辅助检查由 Candidate source 的 Git blobs 生成临时快照，核验 tree/build-input，固定 Go1.25.0、离线模块及隔离环境，编译并绑定测试程序；强制 Candidate 模式，校验三个固定子测试及整体事件，无 skip 降级。真实用户 PATH 只读前后核验，安装使用既有测试替身。
- Wi-Fi 辅助检查要求初始 offline，list 必须恰好一个选定地址，再绑定 status、复核枚举、scan，拒绝逐项 error、遗漏、额外地址、截断或变化；没有认证或 cleanup 路径。
- 三组必需 tuple 精确为 Windows/BHK 有线 password、Wi-Fi password、有线 terminal QR；NAS password/QR 和 BHK Wi-Fi QR 仅为可选采集。两辅助摘要必须分别为安装/Wi-Fi pass，同 Candidate/source/build-input；不能混入认证 evidence_ids。

## 安装缺口定位

历史原生终端回执与 10 月 28 日日志已经支持 direct/junction 执行及多项安装测试通过；不能把工具上下文的问题概括成已证明的产品安装器缺陷。本轮使用独立 D 盘测试目录完成复验。

具体修复为：测试目录 owner 已正确时只收紧 DACL，不额外要求 WRITE_OWNER；PowerShell 非终止错误改为立即失败，写后核验；evidence 文件同样在 owner 已正确时避免冗余 owner 写入。原 installer 的 ACL、reparse、junction 执行和事务断言保持。故意收紧删除权限的两个测试在断言之后恢复其新 fixture 的删除权，未修改真实目录权限。

输出上限测试另发现嵌入 bytes.Buffer 会暴露绕过自定义 Write 的方法；辅助/拓扑缓冲区改为组合，保留限额和溢出拒绝。测试未删除、未降低成功期望。

## P5 进入清单

1. 经后续授权把 P3/P4 审阅后的源码进入受保护 main；核对 source/tree/build-input 与候选 CI，保留签名、祖先关系和原差异白名单。
2. 正式 CI 生成新不可变 Candidate，完成既有六平台构建、原生安装、artifact/attestation 校验。现有旧 Candidate 不可配新 helper。
3. 用新 Candidate helper 取得 BHK 原生安装辅助记录；单独授权 Wi-Fi 辅助窗口，再取得三组必需认证证据。每次确认当前现场条件，凭据仍由维护者私有 TTY 输入。
