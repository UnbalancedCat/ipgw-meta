### 单次窗口动作与边界

需要另行授权一次网页 QR 登录、三次普通产品 status、满足身份条件后的一次产品 logout。BHKDesktop 原生 Windows、有线独占、TUN 关闭、初始账号 offline，十分钟主动操作窗口内保持拓扑不变。一次授权不包含新的扫码重试、刷新二维码、额外查询或其他账号认证。

1. 私有终端执行初始 status，仅 offline 且命令成功可继续；online、unknown、错误均停止。新建一个独立无痕会话，既有无痕窗口如会共享会话则先由维护者决定结束旧无痕会话或停止，不关闭个人普通窗口。
2. 在该无痕标签页先打开 DevTools Network，选 All、启用 Keep log/Preserve log，清除显示过滤（不是清 Cookie），关闭截图录制；然后导航 HTTPS 网关首页，沿正常“连接网络”入口进入 CAS。若打开新标签页，在该标签页附加 DevTools 后再选二维码，不为补记录刷新/重放登录请求。浏览器自动跳过 QR 或额外挑战时停止。
3. 维护者只进行一次扫码及手机确认，观察未扫描到确认后的桌面变化；不点击重新生成二维码、不循环重试。初始页面已经显示 QR 时该轮即计一次。网页或脚本自动刷新生成另一 UUID 时停止并记录“二维码已替换”，不扫描新码。进入新页/成功页不等于目标账号在线。
4. 页面流程结束后私有终端执行第二次 status；只回传 offline/目标账号 online/其他账号 online/unknown 及退出码类别。失败、账号不符、未知或拓扑变化则停止，不执行产品或网页注销。
5. 目标账号在线且条件持续满足时，执行一次普通产品 logout，再执行第三次 status；保持业务成功与最终 offline 分别记录，不因后者成功就覆盖前者失败。不点击网页注销，不请求 CAS logout。完成/停止后结束该无痕会话；关闭窗口不证明服务端 CAS 会话已撤销。

如 logout 返回明确失败仍可执行已授权的最后一次只读 status，但拓扑变化、硬中断或整体窗口已到期则不再发送请求，状态记 unknown。失败不追加 cleanup 或自动重试。恢复管理连接由维护者在进程结束后恢复原有线/Clash 配置，不能用恢复联网推定账号状态。

这是维护者操作的普通浏览器/CLI 对照，没有正式 runner 的持续拓扑监测、统一 Cookie 会话或清理所有权保证。显式绑定只约束产品请求；记录浏览器代理和路径可确认的事实，无法证明同路径就不作同路径推断。Chrome 站点脚本、资源、后台流量及系统 DNS/PKI 可能联网或更新缓存，不承诺精确 GET/DNS/TCP 总数；十分钟截止只停止主动动作，不能保证所有后台请求立即结束。

### 桌面材料清单与后续判断

Agent 在扫码、原始 Network 查看及脱敏期间不截图、不读页面；维护者确认安全源码可查看后才恢复相应读取。每次只交付一个完整操作步骤，等待结果，不要求用户一次粘贴全场原始记录。

依次观察创建/首次等待/扫码后/确认后/网关接续的请求类别；每类仅返回以下允许材料：

- 方法、无查询值的路径、参数键、HTTP 状态、请求先后与固定状态分类。
- body 是空、空白、JSON object、JSONP、HTML 或其他；对象只给经脱敏的字段名与类型，固定状态常量须确认无敏感信息后才提供。
- UUID/service 是否在相关步骤相等或延续，只返回关系，不返回值；跳转只给相对/绝对、同源 CAS/预期网关/其他及是否含敏感字段的分类。
- Sources 中 loginQRCode 的构造、generateLoginQRCode、轮询与回调实现；只提供已核对不含会话材料的相关函数，不保存完整登录 HTML、隐藏字段或脚本中的用户数据。

不导出 HAR、Copy as cURL、headers、二维码图片/payload、UUID、Cookie、ticket、原始正文、完整认证 URL 或手机截图。Cookie 是否使同一会话成立可结合源码分析；不要求从 Headers/Storage 回传 Cookie 名值。桌面无法看见手机全部链路，手机只按官方正常流程操作，不安装代理或证书。

若网页契约足以支持具体缺陷，先更新对应规范/ADR，以新生成合成数据复现并最小修复。若只得到网页成功而不能区分产品失败阶段，集中列缺口，不重复同包、不追加大而全的诊断器；是否需要 QR 专用被动观察另行确定。未来开发 QR 命令与随后 status 各自记录退出/分类，不把合成正式步骤误当原始命令轨迹；正式历史格式不重写。

## 2026-10-31 当前工作包：Chrome 注销对照

维护者已确认 [ADR-0023](../architecture/decisions/ADR-0023-browser-logout-comparison.md)。目标是建立网页实际请求、响应封装和成功判断的关系；不是重开取键或 CTL 研究。旧版本仅作源码对照，不运行、不启用 debug；其日志会包含带账号的请求 URL 和原始响应，且旧代码没有解析业务成功或复核 offline。

### 准备与静态证据

使用现有 Chrome，先读取已加载或维护者已提供且可安全查看的相关源码。定位注销按钮到请求函数的调用链、方法/端点路径/参数键、响应类型设置、重定向及成功/失败/刷新分支。静态可达不冒充实际执行；无法安全查看整页时只接收脱敏的相关函数片段。

不执行 Console 代码，不重放请求，不导航/刷新/主动取缺失资源；新增资源获取归入之后另行授权的真实窗口。已有 Network 记录先由维护者私下检查并脱敏，无法确认窗口和账号归属则只作历史参考。打开 Sources 前由维护者确认没有展示 Headers、Cookies、Response、Preview 原文；该确认不授权认证动作。

当前独立浏览器 r4 实验整体失败（8项通过、2项失败），两种重定向场景中未知 loopback 目标收到请求。它不能证明真实浏览器具备全目标、全跳转阻断能力。本次不将该脚本改成真实采集工具，也不沿用其请求预算或隔离保证。下文旧取键约定保留历史意义。

### 单次真实窗口（尚未授权）

本地网页脚本的normal注销在成功处理后导航至CAS退出路径；维护者提供的配置已确认MacAuth及两个双栈开关均false，因此该静态路径不追加另一IP栈请求，见[静态对照](../research/logout-browser-context-2026-10-31.md)。申请窗口时须说明并确认CAS会话退出影响。一次网页点击不等同于一次HTTP请求，现有计划不构成对未说明CAS会话退出的真实授权。不得为避开影响自行改写页面、注入回调或拦截请求。若窗口中的配置与已核对材料不同，先停止重新确定范围。

需要新的运行时材料时，单独申请一个十分钟主动操作窗口：BHKDesktop 原生 Windows、TUN关闭、有线独占、初始账号offline、期间拓扑不变。Chrome使用现有会话，不清Cookie、改代理/浏览器安全设置或自动切换账号。浏览器执行站点脚本、资源获取与缓存、系统DNS/PKI活动均可能发生；不承诺精确GET/DNS/TCP总数。代理和路径能确认多少记录多少，无法与SDK对齐时仅作浏览器行为参考。

最多一次网页登录、一次网页注销，外加三次普通产品只读status。每次只给维护者一个完整、自包含步骤，等待结果后继续：

1. 私有终端确认初始offline；若online/unknown，停止，不自动注销既有会话。
2. 维护者私下完成一次网页登录，然后在私有终端确认预期账号online；失败、账号不符或出现额外认证挑战时停止。
3. 维护者在DevTools记录所需请求后私下执行网页注销一次，再于私有终端确认offline；失败/unknown时保留结果，不重复注销、不自动切换SDK cleanup。

status使用已绑定普通产品EXE、现有prompt profile和经本地只读核对的同一选定有线IPv4；只执行status，不调用密码provider。执行前核验产品哈希，生成包含实际本地绑定地址的完整命令，不让维护者猜占位符。账号/IP输出留在维护者私有终端，只回传offline、目标账号online或unknown类别及命令成功/失败。不得把登录页停留或公网访问能力当作状态确认。

登录、原始Network内容查看及脱敏期间，Agent暂停截图和页面读取；维护者返回安全材料或明确“Sources已就绪”后才恢复相应读取。窗口到时停止主动动作，不声称能终止所有浏览器后台流量或自动恢复账号状态。失败恢复由维护者决定，不擅自额外认证；管理连接需要恢复时重新开启原Clash TUN，保留核心、代理和节点。

### 可保存材料与判据

禁止HAR、Copy as cURL、Cookie、请求头、完整认证URL和原始响应全文。允许保存经维护者确认的：方法、无查询值端点路径、参数键、HTTP状态、重定向类别；保留完整封装和字段类型的脱敏结构；网页明确比较且无敏感信息的协议常量与相关处理代码；响应是否完整等于该常量及网页实际进入的分支。

若响应是一个固定标记，保存“源码常量＋维护者确认完整相等”，不要求粘贴原始响应。动态账号/IP/时间/会话材料使用明确占位，不能凭占位样例宣称精确字节匹配。无法判断或脱敏则停止该项，不输出原文、不伪造已观察字段。不同窗口、端点、会话和请求上下文分别标识；网页宽松判断不是产品安全成功契约。

交付请求/源码/响应矩阵、状态时间线、证据等级与缺口，并更新当前状态与交接。具体契约成立后才以新生成材料复现精确成功/失败、畸形/截断/冲突/伪成功，提出最小修复方案，保留业务成功与最终offline双重要求。本包不实施产品修改、SDK password_core、Candidate、提交或发布。Chrome对照不替代后续修复包真实闭环或正式Candidate验收。

## 历史：2026-10-30 浏览器取键离线可行性

维护者于 2026-10-30 明确批准独立 Playwright/CDP 离线准备。该历史范围仅为合成浏览器实验，不是校园工具或真实窗口授权；产品、公共契约、Candidate 与正式门禁不变。研究依据见 [提交上下文研究](../research/cas-submit-context-2026-10-30.md)。

复用已有本机 Chrome 和 bundled Playwright；独立临时浏览器进程及非持久 context，不连接个人浏览器调试端口，不读取个人配置、Cookie 或密码。仅监听回环接口的合成服务器与拒绝代理；全部 fixture 来源固定为本次回环服务器，不能从参数接受真实 URL。代理只拒绝、不转发，DNS 映射限制属于进程级补充，不宣称是操作系统防火墙或全部系统流量证明。不禁用 Chromium 沙盒或 TLS 校验。

在首个页面创建前建立 context 级 HTTP 与 WebSocket 拦截；阻断非 GET、非精确 fixture 路径、未知 query、popup/iframe 的未知目标，service worker 禁用。独立合成用例核对 form、fetch、XHR、beacon、重定向、worker、WebSocket、popup/iframe 与预算停止；服务器端记录只包含固定 fixture 名和方法，验证被拒绝目标未收到请求。不仅依靠浏览器 API 的 aborted 事件判断阻断。

CDP 仅对生成脚本设置已知断点、读取内存脚本并比较内容，在合成调用帧内比较生成公钥的相等关系；报告只保留分类和布尔值。合成事件处理器允许调用无凭据的测试函数，以证明文本候选与真正函数参数可以不同；不是授权触发真实登录处理器。独立 context 之间的合成 Cookie/localStorage 不继承，并验证首轮 context 为空。

实验自身最多 90 秒，单用例最多 8 秒；每 context 请求预算固定且同步计数，超限停止。保留浏览器/Playwright/Node 版本、脚本 SHA-256、逐项通过/失败、loopback sink 计数与能力限制；不保存 HAR、trace、截图、正文、原始 CDP 数据或个人材料。临时 profile 仅含合成数据，关闭测试浏览器；不清理个人浏览器或既有产物。

退出条件是交付可重复实验及实际结果，不要求全部假设通过。某类旁路无法控制、观察改变语义、原生浏览器不可用或资源保护不充分时明确报告；不临时扩大权限或把普通浏览器导航称为零 POST。实际校园方案必须另行固定来源、浏览器自动请求/缓存影响、预算与停止条件，并取得新的单次授权。本实验不会提供真实模式开关。

参考官方能力边界：[Playwright context routing](https://playwright.dev/docs/api/class-browsercontext#browser-context-route)、[service worker 限制](https://playwright.dev/docs/service-workers)、[CDP Debugger](https://chromedevtools.github.io/devtools-protocol/tot/Debugger/)。这些机制分别承担请求拦截、worker 管理和断点观察；不能互相代替，更不能单凭源码调用链证明真实事件已执行。
