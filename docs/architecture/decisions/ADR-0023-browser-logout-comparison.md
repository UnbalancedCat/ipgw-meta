# ADR-0023：Chrome 注销响应与旧版行为对照

2026-10-31 维护者批准本工作包：使用现有 Chrome 分工，维护者私密认证并先脱敏，Agent 分析允许的源码/材料；旧版只读比较。批准实施不授权新的真实窗口。

依据是 [ADR-0022](ADR-0022-development-logout-structure.md) 新包一次运行将首次注销失败收敛为完整正文的封装未识别，登录再次成功；当前不能从 other 推断实际格式或成功语义。[当前状态](../../upgrade/status.md#status-20261031-logout-envelope) 保留完整证据边界。

先核对已加载的网页注销调用链和已有记录，再决定是否需要一次网页登录/注销与三次普通产品只读 status。具体流程、材料投影、授权及停止条件见[浏览器注销对照约定](../../operations/browser-comparison.md#browser-logout-comparison)。不修改 SDK/CLI/JSON/退出码或注销成功判据，不执行旧版或其原始 debug 日志，不延伸旧取键实验的隔离承诺。

维护者先私下检查原始 Network 内容，只向 Agent 提供脱敏结构、字段类型和网页明确比较且确认无敏感信息的协议常量。单个固定标记通过“源码常量＋完整相等关系”记录，不要求原始响应全文。其余真实认证材料继续不得落盘。不能安全脱敏则保留缺口。

网页登录/注销、原始 Network 检查及脱敏期间，Agent 不截图或读取页面。旧版成功提示、网页成功提示、HTTP200 或后续 offline 均不能单独替代现有业务成功与状态验证。不同端点/上下文/路径分别记证据，不自动移植 UA、Referer 或 Cookie 行为。

只有具体契约依据成立后，才能建立相应合成样例与后续最小修复方案；本工作包不直接修改产品 parser。材料不足时以证据不足结束，不为了获得通过继续加标签或重复校园测试。
